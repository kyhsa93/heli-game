# 아파치: 카르다 전선 — 게임 기획 문서

> **2026-09-30 소유자 결정 — 방향 전환.** 캠페인(12임무)·훈련·즉시 출격 등 기존 아파치 조종 콘텐츠는 게임에서 제거했다. 게임은 봇과 함께 혼자 하는 배틀필드식 대규모 전투 **"전장"** 모드로 다시 만든다. 새 기획은 저장소 위키(https://github.com/kyhsa93/karda/wiki)가 기준이다. 아파치 기체(비행 모델·무장·센서·조종석)와 엔진(sim·render·audio·input)은 전장의 탈것·기반으로 재사용하려고 남겼다. 이 폴더의 문서는 남은 엔진의 설명과 옛 기획 기록으로만 읽는다. 단 [01-vision.md](01-vision.md)와 [09-roadmap.md](09-roadmap.md)는 전장 기준으로 1차 개정했다(B1-16).

이 폴더는 현재의 "AH-64 조종 시뮬레이터"를 **아파치 조종사로 전쟁을 수행하는 게임**으로 확장하기 위한 기획 문서다. 개발 에이전트가 이 문서만 읽고 작업 단위를 골라 구현할 수 있도록, 기획 의도·규칙·수치·화면 구성·코드 구조·작업 순서를 모두 담는다.

## 문서 사용 규칙 (개발 에이전트용)

1. **작업은 [09-roadmap.md](09-roadmap.md)의 작업 ID 단위로 한다.** 각 작업에는 관련 문서 절, 건드릴 파일, 완료 조건이 적혀 있다. 앞 마일스톤이 끝나기 전에 뒤 마일스톤 작업을 시작하지 않는다(의존 관계 표 참고).
2. **수치의 원본은 한 곳뿐이다.** 무장 수치는 04, 유닛 수치는 05, 비행 수치는 03에 있다. 구현할 때는 이 표를 `src/content/*.json`으로 옮기고, 이후 밸런스 조정은 JSON에서 한다. 문서와 JSON이 다르면 JSON이 최신이고, 작업을 끝낼 때 문서 표도 같이 고친다.
3. **"결정됨"과 "미정"을 구분한다.** 문서 안의 `> 미정:` 블록은 아직 소유자 결정이 필요한 항목이다. 미정 항목에 닿는 작업은 문서에 적힌 기본안으로 구현하고, 커밋 메시지에 기본안을 택했다고 적는다.
4. **현재 동작을 깨지 않는다.** 지금 있는 비행 모델·착륙 판정·계기·PWA 동작은 이 게임의 토대다. 리팩터링은 기존 테스트(`src/sim3d/sim.test.ts`, `src/sw.test.ts`)가 그대로 통과하는 상태로 한다. 예외는 로드맵 M0-2가 명시적으로 삭제하는 화물 배달 테스트 하나뿐이다.
5. **문서도 코드처럼 갱신한다.** 구현하면서 기획과 다르게 결정한 것은 해당 문서를 같이 고친다. 로드맵의 작업 상태 체크박스도 갱신한다.

## 한 줄 요약

> 가상의 산악 전선 "카르다"에서, 플레이어는 AH-64D 아파치의 뒷좌석 조종사가 되어 지형 뒤에 숨어 접근하고(NOE), 센서로 적을 찾아 식별하고, 헬파이어·로켓·기관포로 교전한 뒤, 살아서 전방 재보급 지점(FARP)으로 돌아온다. 12개 임무 캠페인에서 전선이 움직인다.
